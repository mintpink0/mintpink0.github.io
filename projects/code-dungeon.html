02 — Data Flow툴에서 게임까지

네비게이션 메시는 툴에서 찍어 파일로 저장하면 엔진이 읽어 들이고, 게임에서는 캐릭터마다 나눠 사용합니다. 아래 그림은 각 단계가 앞 단계에 기대는 조건을 한 장에 정리한 것입니다.

툴 좌표 보정 — 엔진은 두 셀이 한 변의 두 꼭짓점 좌표를 정확히 같게 가질 때만 그 변으로 이웃을 연결합니다(XMVector3Equal 비교). 마우스로 찍은 점은 조금씩 어긋나므로, 툴에서 기존 꼭짓점 반경 1.5 안을 찍으면 그 꼭짓점 좌표를 그대로 쓰게 했습니다. 이 스냅이 있어야 엔진의 연결 조건이 맞습니다.

03 — Navigation Mesh네비게이션 메시와 계단

삼각형 셀을 Cell → Navigation(셀 묶음) → Region → Stage 순으로 쌓았습니다. 위 단계가 아래 단계를 SHPTR로 소유하고, 셀끼리의 이웃은 포인터가 아닌 int 인덱스로 가리킵니다.

클래스가진 것하는 일
UCell꼭짓점 3 · 변 · 법선 · 이웃 인덱스 · 점프 가능 여부점이 셀 안인지 판정(IsIn)
UNavigation셀 컨테이너 · 현재 셀이동 검사(IsMove), 셀 찾기, 높이 계산, 경계 위치 보정, 경로 탐색
URegionNavigation 하나구역 단위 저장 · 불러오기
UStageRegion 목록폴더 단위 저장 · 불러오기

IsIn은 세 변마다 XZ 평면의 바깥 법선과 내적해 점이 셀 안인지 봅니다. 바깥이면 그 변 너머 이웃의 번호를 돌려주고, IsMove는 그 번호를 따라 최대 10번 이웃을 옮겨 가며 위치를 품은 셀을 찾습니다. 찾지 못하면 false를 돌려주고, 호출한 쪽이 경계 위치 보정을 합니다.

셀 데이터는 공유, 현재 셀만 캐릭터별

플레이어 · 몬스터 · 할리퀸의 수리검은 각자 Navigation을 복제하여 사용합니다. 셀 데이터는 하나고 지금 어느 셀에 있는가에 대한 정보만 각자 가집니다. 카메라도 자기 Navigation과 현재 셀을 따로 둡니다.

구역을 하나로 합친 결정

처음에는 맵을 Region 단위로 나누고 플레이어가 있는 Region만 쓰는 최적화를 의도했습니다. 그런데 Region 경계를 넘을 때 이동 판정 버그가 계속 생겼고 체감 성능 이득이 없어, 맵 전체를 Region 하나로 합치기로 결정했습니다. 이웃 Region을 연결하던 그래프(Add_NeighborRegion)는 쓰이지 않는 코드로 남아 있습니다.

셀이 한 Navigation에 모두 모였으므로, 셀 찾기(FindCell)는 현재 셀 번호 ±25 범위부터 보고 못 찾으면 25씩 넓힙니다. 최악에는 전체를 봅니다. 셀 번호는 툴에서 만든 순서대로 붙어, 이어서 찍은 셀끼리는 번호도 가깝습니다.

계단에서 캐릭터가 순간이동하던 문제

나선 계단
상황
나선 계단을 오르내릴 때 캐릭터가 위층이나 아래층으로 순간이동했습니다.
원인
IsIn은 XZ 평면만 보는 반평면 판정이라 높이를 모릅니다. 위아래로 겹친 셀은 평면상 같은 자리라 둘 다 「안쪽」이 되어, 먼저 찾은 다른 층 셀이 선택됐습니다.
해결
이웃 연결(위상)과 높이(기하) 두 쪽으로 나눠 고쳤습니다. 평소에는 현재 셀에서 이웃을 따라 걸어서 층이 바뀌지 않습니다(겹친 층끼리는 변을 공유하지 않음). 현재 셀을 새로 찾아야 할 때(FindCell)는 후보 중 높이 차가 가장 작은 셀을 고르게 했습니다.
다시 만든다면
이 높이 차는 부호가 있는 값(캐릭터 y − 셀 높이)이라, 머리 위에 겹친 셀이 음수로 더 작게 나와 뽑힐 수 있습니다. 발밑 셀(높이 차 ≥ −ε)만 후보로 두겠습니다.

04 — Movement · Camera이동 · 카메라

  • 점프 가능 셀 — 셀에 점프 가능 토글을 두고, 그 셀에서 경계를 넘으면 FindCell로 아래 셀을 찾아 낙하를 시작합니다. y가 셀 높이보다 낮아지면 착지로 보고 위치를 맞춥니다. 점프 · 낙하 중이 아니면 셀 높이를 탑니다.
  • 경계 위치 보정 — 현재 셀 밖으로 나가면 셀의 세 변 중 가장 가까운 변 위의 점으로 XZ만 옮기고 높이는 유지합니다. 그 점이 꼭짓점이면 그 꼭짓점을 공유하는 이웃 셀로 현재 셀을 바꿉니다. 이 보정은 몬스터와 카메라에 사용합니다.
  • 카메라 — 카메라는 자기 Navigation과 스폰 셀을 따로 둡니다. 플레이어와 30 이내면 이동에 실패할 때 XZ만 경계로 보정하고 높이는 유지합니다. 30을 넘으면 플레이어 위치로 되돌리고 그 자리의 셀을 다시 찾습니다.

05 — Monster AI몬스터 4종

팀장이 만든 애니메이션 컨트롤러 프레임워크가 상태에 맞는 애니메이션을 재생하고 루트 모션을 처리합니다. 저는 그 위에서 몬스터마다 상태를 바꾸는 조건(거리 · 피격 횟수 · 타이머)을 작성했습니다.

  • 감지 · 해제 거리 분리 — 감지 거리 안으로 들어오면 추적을 시작하고, 그보다 먼 해제 거리 밖으로 나가야 추적을 멈춥니다(CMob::SearchForPlayers). 경계 근처에서 추적이 켜졌다 꺼졌다 깜빡이지 않게 하는 이중 임계값입니다.
  • 추격 이동 — A* 경로는 방향만 정합니다(MoveAlongPath는 다음 목표 점만 갱신). 실제 이동은 현재 애니메이션 상태별 고정 속도로 옮깁니다.
  • 배회 · 복귀 — 플레이어를 찾지 못하면 미라 · 미노타우르스 · 할리퀸은 5초마다 이웃 셀을 무작위로 세 번 건너간 셀을 골라 그쪽으로 경로를 찾습니다. 아누비스는 원래 자리로 돌아갑니다.
몬스터감지 / 해제패턴
미라50 / 80누운 형태 · 선 형태 2종. 범위에 들어오면 관이 열리며 일어나 도발 후 추적. 손 휘두르기 2종, 맞으면 짧은 경직. 멀어지면 주변 이웃 셀을 골라 배회

06 — Player플레이어

  • 콤보 — 좌클릭 · 우클릭 각각 3단계. 앞 단계가 재생 중일 때 다시 눌러야 다음 단계로 이어지고, 아니면 1단계부터 시작합니다.
  • 스킬 3종(Q · 1 · 2) — 각자 쿨타임이 있고, 다른 스킬이 시전 중이면 시작하지 않아 동시에 쓸 수 없습니다.
  • 점프 제한 — 구르기 · 피격 · 기상 · 콤보 · 스킬 동작 중에는 점프 입력을 받지 않습니다.
  • 구르기 — 구르기 · 점프 · 기상 중에는 피격 콜라이더 크기를 0으로 줄이고, 구르다 벽에 닿으면 직전 위치로 되돌립니다.
  • 넉백 · 기상 — 넉백 공격에 맞으면 몬스터가 보는 방향으로 플레이어를 돌린 뒤, 넉백 애니메이션의 루트 모션으로 약 1.75초 동안 밀어냅니다. 2초가 지나면 Space로 일어나고, 기상 중에는 피격을 무시합니다. 아누비스 보호막에 밀릴 때는 아누비스가 보는 방향의 반대로 돌립니다.

07 — Path FindingA* 길찾기

네비게이션 메시의 셀을 노드로 삼아 몬스터가 플레이어까지의 경로를 찾습니다.

  • 비용 — 노드에 F = g + h를 두고 우선순위 큐로 정렬합니다. 간선 비용 g와 휴리스틱 h 모두 셀 중심 사이의 3D 맨해튼 거리(|dx| + |dy| + |dz|)를 사용합니다. 맵이 실내 던전이라 기둥 같은 장애물이 많아, 이 거리가 더 유리하다고 판단했습니다.
  • 프레임 분할 — 탐색 상태(열린 목록, 비용, 이전 셀, 완료 여부, 경로)를 구조체에 담아 한 프레임에 노드 하나씩 진행합니다.
  • 도착 판정 — 몬스터의 현재 셀과 플레이어의 현재 셀은 같은 셀 컨테이너의 원소라 포인터로 비교합니다.
  • 재탐색 — 플레이어를 쫓는 몬스터는 1초마다(아누비스는 0.5초) 경로를 다시 찾습니다.
  • 직선화 — 메시 위에서 2.0 간격으로 가시선 검사를 해 직선으로 갈 수 있는 중간 점은 건너뛰어 지그재그 움직임을 줄였습니다.
if (GetTimeAccumulator() >= 1.0) {                     // 1초마다 새로 시작
    m_PathFindingState = spNavigation->StartPathFinding(
        CurrentMobPos, CurrentPlayerPos, CurrentMobCell, CurrentPlayerCell);
    m_isPathFinding = true;
    SetTimeAccumulator(0.0);
}
if (m_isPathFinding) {
    if (spNavigation->StepPathFinding(m_PathFindingState)) {  // 프레임당 노드 하나
        m_isPathFinding = false;
        if (m_PathFindingState.pathFound) {
            m_AstarPath = spNavigation->OptimizePath(          // 가시선으로 직선화
                m_PathFindingState.path, CurrentMobPos, CurrentPlayerPos);
            m_currentPathIndex = 0;
        }
    }
}

08 — ImGui Tools편집 툴 2종

편집 로직은 엔진의 Region · Stage에 빌드 플래그(_EDIT_NAVI)로 넣고, Tool 프로젝트의 NavigationView가 이를 호출합니다. 모델 배치(레벨) 툴도 같은 Tool 프로젝트에 있습니다.

네비게이션 편집

맵 모델을 띄우고 픽킹으로 셀을 찍어 메시를 만듭니다. 「Modify Navigation」을 켜면 편집이 시작됩니다.

  • 셀 생성 — 픽킹할 때마다 그 위치에 큐브를 두고, 세 번째 클릭에서 셀을 만듭니다. 기존 꼭짓점 반경 1.5 안을 찍으면 그 꼭짓점 좌표를 그대로 써서 엔진이 이웃으로 연결하게 했습니다(02 참고).
  • 셀 번호 — 새 셀의 번호는 그때까지의 셀 개수, 즉 만든 순서입니다. 셀을 지우면 번호를 다시 매기고 이웃을 다시 계산합니다.
  • 되돌리기 — BackSpace로 꼭짓점 설정 중이면 마지막 픽킹을, 아니면 마지막 셀을 지웁니다.
  • 지연 삭제 — ImGui가 셀 목록을 순회하는 도중 삭제하지 않도록, 지울 셀을 set에 모아 다음 Tick 맨 앞에서 한꺼번에 지우고 번호 재부여 · 이웃 재계산을 합니다. 엔진 UActorGroup과 같은 지연 삭제 패턴입니다.
  • 렌더 범위 지정 — 셀이 많아지면 디버그 큐브도 늘어 프레임이 떨어져, 그릴 셀의 번호 범위를 정할 수 있게 했습니다.
  • 셀 검사 — Pick_On_Cell로 셀을 골라 번호 · 이웃 번호를 보고, 점프 가능 여부를 바꾸거나 지웁니다. 번호 오류를 이웃 정보로 찾아 고쳤습니다.
  • 저장 · 불러오기 — Region마다 이름을 붙여 Navigation 폴더에 파일로 저장하고, 폴더째 다시 불러옵니다.

모델 배치(레벨) 툴

맵 모델 · 오브젝트 · 몬스터의 변환을 한 화면에서 편집하고 바이너리 파일로 저장해 클라이언트에서 불러 쓰는 레벨 툴입니다.

맵 모델 · 오브젝트 · 몬스터 모델을 목록에서 골라 배치하고, 배치 묶음을 MapLayouts로 저장하고 불러옵니다. 일반 모델(ModelViewer)과 애니메이션 모델(AnimModelViewer)을 따로 다루고, ImGuizmo로 이동 · 회전 · 크기를 직접 조작합니다.

09 — Limits한계와 다시 만든다면

한계다시 만든다면
셀 번호 하드코딩플레이어 시작(23), 캐릭터 Navigation 시작(703), 게임 종료 트리거(1141)가 셀 번호에 묶여 있어, 툴에서 셀 하나만 지워도 번호가 당겨져 어긋납니다. → 맵에 스폰 · 트리거 마커를 두고 위치로 셀을 찾겠습니다.
네비게이션 툴 최적화셀이 많아지면 꼭짓점마다 그리는 디버그 큐브가 늘어 편집 중 프레임이 떨어졌고, 그릴 셀의 번호 범위를 정하는 것으로만 피했습니다. → 큐브를 한 번에 그리는 인스턴싱이나 화면에 보이는 셀만 그리는 방식으로 바꾸겠습니다.
편집 코드가 엔진에 섞임편집 로직이 엔진 URegion · UStage 안 _EDIT_NAVI 블록에 있습니다. → Tool 쪽 래퍼로 분리하겠습니다.
저장 포맷에 버전 없음셀 정보를 순서대로 기록할 뿐이라 구조가 바뀌면 옛 파일을 구분할 수 없습니다. → 매직 · 버전 헤더를 두겠습니다.
몬스터 로직 중복몬스터 4종이 추격 · 배회 · 복귀의 경로 탐색 블록을 각자 가지고 있습니다. → CMob 또는 경로 추종 컴포넌트로 모으겠습니다.
A* 1초 재시작프레임당 노드 하나라 60fps 기준 초당 약 60노드를 봅니다. 1초마다 새로 시작하므로 그보다 먼 경로는 끝나기 전에 다시 시작될 수 있습니다. → 프레임당 노드 예산을 두고, 탐색 중에는 재시작을 미루겠습니다.
